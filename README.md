# Schedule AD Blocker: Backend-сервис для управления учетными записями

Это бэкенд-сервис, разработанный как полноценное production-ready приложение. Он автоматизирует процесс временного включения и отключения учетных записей пользователей в **Active Directory** на основе заранее созданных расписаний (отпуск, командировка, учеба и т.д.).

Проект состоит из двух частей:
1.  **Backend (этот репозиторий)**: NestJS-приложение, предоставляющее GraphQL API для управления данными и выполняющее всю бизнес-логику.
2.  **Frontend**: Отдельное React-приложение, которое взаимодействует с этим бэкендом, предоставляя пользовательский интерфейс для администраторов.

## 🎯 Ключевая бизнес-задача

Проект решает реальную задачу IT-отделов и отделов безопасности: автоматизация процесса временного отключения и включения учетных записей сотрудников в Active Directory на основе внутренних приказов (отпуск, командировка и т.д.).

Автоматизация этого процесса снижает риски несанкционированного доступа и уменьшает ручную нагрузку на системных администраторов.

## 🌟 Функционал приложения (Frontend + Backend)

Приложение представляет собой комплексное решение с веб-интерфейсом для администраторов, которое позволяет:

### Управление задачами и расписаниями
*   **Создавать и управлять задачами** на временную блокировку/разблокировку учетных записей.
*   Обрабатывать **отзывы сотрудников** из отпуска с автоматической коррекцией расписания.
*   Создавать **"разовые" задачи**, которые выполняются один раз в указанную дату.
*   **Автоматически архивировать** выполненные и отозванные задачи для поддержания чистоты данных.

### Мониторинг и отчетность
*   **Просматривать историю** блокировок по каждому сотруднику.
*   Получать **статистику** по общему количеству дней отсутствия (отпуск, декрет и т.д.).
*   Отслеживать **список активных задач** с возможностью поиска и фильтрации по любому параметру.
*   Просматривать задачи, которые **не удалось выполнить**, с указанием причины сбоя.
*   Получать информацию о сотрудниках **напрямую из Active Directory**.

### Администрирование системы
*   **Управлять Cron-службой** в реальном времени: изменять расписание, запускать принудительно, останавливать и перезапускать.
*   **Контролировать сессию пользователя:** отображается таймер до ее истечения.
*   **Видеть время до следующего запуска** фоновой службы.
*   Работать с **архивом**, где хранятся все типы завершенных задач (основные, разовые, отзывы) с возможностью поиска и фильтрации.

## ✨ Для работодателя: Ключевые продемонстрированные навыки

*   **Архитектура и проектирование (Backend):**
    *   Приложение построено на **NestJS**, что демонстрирует понимание принципов **модульности**, **Dependency Injection (DI)** и четкого разделения ответственности (Controller/Resolver, Service, Repository).
    *   Код написан на **TypeScript** с использованием строгой типизации, что повышает надежность и упрощает поддержку.
    *   Использован **Prisma ORM** для типобезопасного взаимодействия с базой данных PostgreSQL, включая управление миграциями (`prisma migrate deploy`).

*   **Интеграция с корпоративными системами (LDAP):**
    *   Реализована глубокая интеграция с **Active Directory** через протокол **LDAP**. Это включает не только аутентификацию, но и непосредственное изменение атрибутов пользователей (`logonHours`, `userAccountControl`), что является нетривиальной задачей и востребованным навыком в enterprise-разработке.

*   **Продвинутая и безопасная система аутентификации:**
    *   Реализован двухэтапный механизм: первичный вход через **LDAP**, после чего для всех последующих запросов используются **JWT-токены (Access и Refresh)**.
    *   Продемонстрировано понимание лучших практик безопасности: **Refresh Token** передается в **`httpOnly` cookie** для защиты от XSS-атак. Подробная документация по этому механизму находится в файле `auth.md`.

*   **Реализация сложной бизнес-логики:**
    *   Система обрабатывает не только простые записи, но и связанные сущности (например, "отзыв из отпуска").
    *   Реализован механизм **архивирования** отработанных записей с использованием **транзакций Prisma (`$transaction`)**, что гарантирует целостность данных при переносе информации между таблицами.

*   **Надежное управление фоновыми задачами (Cron):**
    *   Это одна из ключевых и наиболее сложных частей проекта. Создан **продвинутый оркестратор Cron-задач** (`ScheduleCronTaskService`):
        *   **Защита от дублирования запуска (Anti-overlap):** Механизм флагов (`isRunning`) предотвращает повторный запуск задачи, если предыдущий еще не завершился.
        *   **Изоляция и отказоустойчивость:** Каждая подзадача выполняется в обертке с **таймаутом** и собственным `try-catch`, чтобы ошибка в одной операции не останавливала весь процесс.
        *   **Динамическое управление:** Реализован API для управления Cron-задачами **в реальном времени** (старт, стоп, "горячий" запуск, изменение расписания `cron expression`), что является функционалом уровня production-инструментов.

*   **Production-Ready подход:**
    *   **Конфигурация:** Гибкая настройка через переменные окружения (`.env`).
    *   **Логирование:** Настроено детальное логирование с помощью **Winston** с ротацией файлов и разделением логов по контексту (например, `label: 'cron'`).
    *   **Деплой:** Подготовлена подробная инструкция по развертыванию на Windows Server (`DEPLOY_WINDOWS.md`), демонстрирующая понимание полного жизненного цикла приложения.

*   **Проектирование API:**
    *   В качестве API используется **GraphQL**, что позволяет фронтенду запрашивать только необходимые данные.
    *   API строго типизирован, используются `InputTypes` для мутаций и `Filters` для запросов, что делает его надежным и удобным для потребителей.

## 🚀 Основной функционал бэкенда

*   **Управление расписаниями:** CRUD-операции для создания, чтения, обновления и удаления задач на блокировку/разблокировку учетных записей.
*   **Интеграция с Active Directory:** Изменение атрибутов `logonHours` и `userAccountControl` для управления доступом пользователей.
*   **Аутентификация и авторизация:** Вход для администраторов через их учетные данные AD и последующая работа через JWT.
*   **Фоновая обработка:** Автоматический запуск и завершение задач по расписанию с помощью Cron.
*   **Архивирование:** Перенос выполненных и устаревших задач в архивные таблицы для поддержания производительности основной таблицы.
*   **Управление Cron-задачами:** API для мониторинга и управления состоянием фоновых задач.

## 🛠️ Технологический стек

*   **Платформа:** Node.js
*   **Фреймворк:** NestJS
*   **Язык:** TypeScript
*   **API:** GraphQL (Apollo Server)
*   **База данных:** PostgreSQL
*   **ORM:** Prisma

## 🏗️ Архитектура

Приложение имеет классическую для NestJS модульную структуру.

```
Client (React App) <--> GraphQL API <--> NestJS Backend <--> PostgreSQL (Prisma)
                                             ^
                                             |
                                             v
                                     Active Directory (LDAP)
```

*   `AuthModule`: Отвечает за аутентификацию (LDAP + JWT).
*   `LdapModule`: Инкапсулирует всю логику работы с Active Directory.
*   `ScheduleModule`: Основной бизнес-модуль. Содержит логику управления расписаниями (`ScheduleService`), GraphQL-резолверы (`ScheduleResolver`) и сервис управления Cron-задачами (`ScheduleCronTaskService`).
*   `PrismaModule`: Сервис для работы с базой данных через Prisma.

## 🚀 Деплой и запуск

Проект готов к развертыванию. В файле `DEPLOY_WINDOWS.md` описаны три способа деплоя на Windows Server:
1.  **NSSM (рекомендуется):** Запуск приложения как надежной Windows-службы.
2.  **PM2:** Использование process-менеджера для управления приложением.
3.  **Планировщик задач Windows:** Базовый вариант без сторонних утилит.

Для локального запуска необходимо:
1.  Настроить файл `.env` с доступами к БД и Active Directory.
2.  Установить зависимости: `npm install`.
3.  Применить миграции БД: `npx prisma migrate deploy`.
4.  Запустить в режиме разработки: `npm run start:dev`.
